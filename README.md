# 한국 시장 데일리 보고서

코딩 초보자를 위한 첫 실행 가능한 기반입니다. **전체 분석 서비스 완성본은 아닙니다.** 데이터 접근과 분류 근거가 없으면 숫자·기사 요약을 만들어 내지 않습니다.

## 파일은 무슨 일을 하나요?

- `src/korea_daily/core.py`: 지수·뉴스 수집, 날짜 필터, 비교 계산, HTML/JSON 저장.
- `src/korea_daily/cli.py`: 실행, 로그, SMTP 발송 및 중복 방지. 기본은 미리보기입니다.
- `tests/test_core.py`: 날짜·누락·중복·비교 계산 검사. 테스트 숫자는 테스트에만 사용합니다.
- `.github/workflows/preview.yml`: PC가 꺼져 있어도 GitHub에서 수동 실행할 미리보기 작업. 자동 예약은 비활성입니다.
- `reports/날짜/실행시각/`: `email-preview.html`, `detail.html`, `data.json`. Git에는 올리지 않습니다.
- `state/`: 실행 로그와 발송 기록. Git에는 올리지 않습니다.
- `docs/providers.md`: 데이터 접근 조사와 미구현 항목.

## 실행 방법

Python 3.11 이상이 필요합니다. 외부 패키지와 API 비용 없이 실행합니다.

```bash
cd /workspace/analyze_Korea
PYTHONPATH=src python -m unittest discover -s tests -v
PYTHONPATH=src python -c 'from korea_daily.cli import main; main()'
```

출력된 `email-preview.html` 파일을 브라우저로 여세요. 수집 실패도 정상적으로 저장되지만, 이는 시장 분석 검증 성공을 뜻하지 않습니다. 재실행은 별도 시각 폴더에 저장합니다. 직전 보고서와 같은 관측일이면 재사용으로 표시합니다. 새 작업에서 기존 체크아웃을 사용하고 별도 worktree는 만들 필요가 없습니다.

## 발송 (현재 사용하지 않음)

수신 주소는 아직 확인되지 않았습니다. Gmail 플러그인의 ChatGPT 연결은 독립 Python 프로그램의 Gmail API OAuth 인증을 제공하지 않습니다. 현재 프로그램은 **Gmail API가 아닌 TLS SMTP**를 사용합니다. Gmail은 계정 정책에 따라 2단계 인증과 앱 비밀번호가 필요할 수 있고, 조직 계정은 허용하지 않을 수 있습니다. API OAuth 방식은 미구현입니다.

실제 발송을 명시적으로 승인한 이후에만 환경의 비밀 저장소에 `SMTP_HOST`, `SMTP_PORT`(기본 465), `SMTP_USER`, `SMTP_PASSWORD`, `REPORT_FROM`, `REPORT_TO`를 설정하세요. 비밀번호를 코드, 명령 기록, 보고서 또는 Git에 넣지 마세요. 발송에는 `--send --confirm-live-send` 두 옵션이 모두 필요합니다. 현재 필수 데이터 수집이 실패하면 발송이 중단됩니다. 성공적인 SMTP 테스트는 아직 하지 않았습니다.

일자(KST)·수신자별 SQLite 고유 키를 발송 전에 예약합니다. 동시 실행, 실패 또는 응답 단절 후에도 자동 재시도를 막습니다. 모호한 실패는 수신 여부를 직접 확인해야 합니다. SMTP는 엄밀한 exactly-once 전송을 보장하지 않습니다. `state/`를 지우거나 다른 머신에 복사하지 않으면 중복 방지가 유지되지 않습니다.

## 매일 오전 8시 실행

GitHub Actions의 수동 미리보기는 PC 전원과 무관합니다. 아직 실행하거나 반복 예약을 활성화하지 않았습니다. 명시적 요청 후 UTC `0 23 * * *`(한국 다음 날 오전 8시)를 추가할 수 있습니다. 실행 지연이 가능하며 기본 브랜치에 워크플로가 있어야 합니다. GitHub 요금제별 실행 시간·아티팩트 비용과 저장 한도를 확인해야 합니다. 유료 가입은 하지 않았습니다.

현재 Actions는 매번 새 머신에서 실행하므로 과거 보고서 및 SQLite가 자동 복원되지 않습니다. 반복 발송 전에는 영구 디스크가 있는 클라우드 VM/스케줄러 또는 원격 영구 데이터베이스를 구성해야 합니다. 영구 머신에서는 `TZ=Asia/Seoul`이 적용된 cron/systemd 타이머를 사용할 수 있으나 이 환경에는 crontab이 없습니다. 현재 클라우드 작업의 프로세스 생존을 예약 실행 수단으로 간주하지 않습니다.

## 분석의 한계

지수 관측일은 실행일 이전 값만 사용합니다. **공식 거래일 달력이 없어 직전 완료 거래일·휴장·지연을 정확히 판정하지 못합니다.** 상태를 미확인으로 표시합니다. 거래량을 거래대금으로 바꾸어 표현하지 않습니다. 가격·뉴스 인과관계, 기업 연결, 매수 추천을 생성하지 않습니다. 규칙 기반이며 AI API를 사용하지 않습니다.

실행 가능한 골격과 실패 경로를 검증했지만, 외부 제공처 차단 때문에 실데이터 분석은 미검증입니다. 단계별 남은 작업은 `docs/providers.md`를 보세요.
